What the library file says the normalizer derives (see `05-captions.md` and `06-credits.md` for what engine 0.1.48 actually builds):

- `cursor.position.keys`: one key per move: `{ t: move.t, v: [move.x, move.y], ease: $theme.ease.move, path: "auto" }`; a move whose `t` equals the previous `t` + 0 holds (ease `hold`) so the cursor can rest; keys are layer times (the layer has no offset)
- `cursor.scale.keys (click dip)`: for each `click`: scale ×0.85 over 0.08 s with `power2.out` at `t`, back to ×1 over 0.2 s with `back.out(2)`
- `rig zoom`: for each move with `zoom` > 1: `rig.anchor` set to `[x, y]` and `rig.position` to `[x, y]` (hold) at `t + 0.15`, then `rig.scale` → `zoom × 100` over `zoomDur` with `$theme.ease.move`; the next move with `zoom` ≤ 1 returns scale to 100 over `zoomDur`; `content` and `ripples` inherit through the parent
- `duration`: `auto` = last move `t` + 0.6 s (ripple length) + any outstanding zoom-out

Notes from the library file:

- Engine-backed in one place: there is no construct that turns a list param into keyframes, so the cursor's position keys, its click dips, and the rig's zoom keys are derived by the normalizer (`x-engine`). The click ripples are fully in-grammar: a `repeat` over `moves` whose template uses `in`/`offset` from `$item.t`, so each ripple's layer-time keys start at its own click.
