What the library file says the normalizer derives (see `05-captions.md` and `06-credits.md` for what engine 0.1.48 actually builds):

- `path`: Replace `line.contents.plot.d` and `area.contents.fillPath.d` from `series`: point i of n is at x = 70 + i · 1260 / (n − 1), y = 620 − (value − min) / (max − min) · 560 (component pixels, clamped to [0, 620]). `plot` is the open polyline through the points, with Catmull-Rom tangents (tension 1/3) when `smooth` is true; `fillPath` is the same path closed down to y = 620 at both ends.
- `ring`: `ring.position` is the last point's position: x is 1330 (the points span the plot width, so the last one is at 70 + 1260 whatever `n`); replace y with the last point's y (the authored 620 assumes it lies on the baseline).
- `why`: The `{{ }}` grammar can place one item per repeat index but cannot build one value (a path) from all items; a `map`/`join` or a `polyline.points: "$props.series"` with field selectors would make this component fully authored.

Notes from the library file:

- Partly engine-backed: the polyline through the data points cannot be written from a list param because the `{{ }}` grammar has no map/iteration over a list (spec 12 §12.4). `x-engine.derives.path` states exactly how the normalizer builds it; everything else (dots, labels, timing) is in-grammar.
- The dots' stagger uses `amount: drawDur` with the same `expo.inOut` distribution as the line draw, so each dot pops when the line passes it (arc-length progress and x progress coincide only for evenly spaced points on a gentle curve; good enough for this chart). `$props.color.a20` applies a color modifier to a param value: spec 12 §12.1.3 defines modifiers on theme colors, so this is an assumption raised as a signal.
