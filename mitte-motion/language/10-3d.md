# 10. 3D: layers and materials, cameras and depth of field, camera sugar, lights, the classic renderer, ordering, nested comps

Scope: spec 8 (the classic 2.5D renderer; the advanced renderer's fields are listed as interchange-only). Generated tables: `Material`, `CastsShadows`, `AcceptsShadows`, `CameraType`, `Dof`, `Iris`, `Orbit`, `Dolly`, `DollyZoom`, `Handheld`, `LightKind`, `Falloff`, `Environment`, `Renderer3d`, `Geometry`, `GeometryBevel`, `Primitive`, `PointOrLayer` in `92-schema-types-*.md`.

## 1. Coordinate system and 3D layers

Units are pixels; x right, y down, **z into the screen** (After Effects' left-handed system). A 3D layer at z = 0 under the default camera appears exactly where the 2D layer would. Rotations are clockwise looking along the positive axis, in degrees.

`"threeD": true` makes any drawable layer 3D (solid, shape, text, image, video, comp, adjustment); `camera` and `light` are 3D by nature; a `null` may be 3D as a 3D parent. `position` and `anchor` gain z, `scale` a third component, and rotation becomes `orientation` (quaternion slerp: "point it this way", a key from `[0,0,0]` to `[0,350,0]` turns 10° the short way) plus `rotationX`, `rotationY`, `rotationZ` (Euler numbers: "spin it", 0 → 720 spins twice; `rotationZ` = `rotation`). The final rotation is `Rz · Ry · Rx · O`. A 2D child of a 3D parent is `layer.parent_2d_to_3d`. `autoOrient: "camera"` makes billboards. `comp.renderer3d` is `classic` (the only renderable value); `"advanced"`, `geometry` on text/shape layers, and `model` layers are `3d.advanced_not_built` (real 3D comes from 3d-service as a video clip composited in paint order).

## 2. Material options

```jsonc
{ "id": "card", "type": "image", "asset": "poster", "threeD": true,
  "material": { "castsShadows": "on", "acceptsShadows": true, "acceptsLights": true, "lightTransmission": 0,
                "ambient": 100, "diffuse": 50, "specular": 50, "shininess": 5, "metal": 100 } }
```

| Field | Type | Default | Notes |
|---|---|---|---|
| `castsShadows` | `off` \| `on` \| `only` | `off` | `only`: casts shadows but is invisible |
| `lightTransmission` | percent | `0` | light passing through the layer colours its shadow (stained glass); animatable |
| `acceptsShadows` | `true` \| `false` \| `only` | `true` | `only`: a shadow catcher (black at the shadowed fraction, transparent elsewhere); hidden this way whenever the run has a valid light |
| `acceptsLights` | boolean | `true` | `false`: unlit, full brightness |
| `ambient`, `diffuse`, `specular`, `shininess`, `metal` | percent | 100, 50, 50, 5, 100 | classic shading: ambient response, Lambert diffuse, Blinn-Phong specular with exponent `max(1, shininess)`, highlight tinted `lerp(white, card colour, metal/100)`; all animatable |
| `baseColor`, `metallic`, `roughness`, `emissive`, `emissiveIntensity`, `normalMap`, `opacityMode` | | | advanced renderer: accepted for interchange, **no effect** (info `lint.material_field_unused`) |

The same info reports classic fields on a 3D layer in a comp with no enabled light, and `material` on a layer that is not 3D.

## 3. Cameras

```jsonc
{ "id": "cam", "type": "camera", "cameraType": "twoNode",
  "transform": { "position": [960, 540, -2400], "pointOfInterest": [960, 540, 0] },
  "zoom": 2666.7,
  "dof": { "enabled": true, "focusOn": "hero", "aperture": 60, "blurLevel": 100, "iris": "hexagon" } }
```

| Field | Type | Default | Anim. | Notes |
|---|---|---|---|---|
| `cameraType` | `oneNode` \| `twoNode` | `twoNode` | no | two-node aims at `pointOfInterest` (`autoOrient: "pointOfInterest"`); one-node aims with its own orientation and rotations |
| `transform.position` | vector3 | `[w/2, h/2, −zoom]` | yes | |
| `transform.pointOfInterest` | vector3 | `[w/2, h/2, 0]` | yes | two-node only |
| `orientation`, `rotationX`, `rotationY`, `rotationZ` | | `0` | yes | applied after aiming (two-node) or alone (one-node): world matrix `aim · Rz · Ry · Rx · O`; `rotationZ` rolls (positive = clockwise on screen); the up vector falls back to +z within 0.01° of vertical |
| `zoom` | px | `w · 50/36` (2666.7 at 1920) | yes | distance to the plane where 1 layer px = 1 comp px; canonical; clamped 10⁻³–10⁷ |
| `focalLength` | mm | — | yes | authored: `zoom = w · focalLength / filmSize` |
| `fov` | degrees | — | yes | authored: horizontal angle of view, `zoom = (w/2) / tan(fov/2)` |
| `filmSize` | mm | `36` | no | for `focalLength` |
| `dof` | object | `{ "enabled": false }` | | §3.2 |
| `orbit`, `dolly`, `dollyZoom`, `handheld` | sugar | | | §4 |
| `solve` | object | | | camera track (P3, not built) |

Exactly one of `zoom`, `focalLength`, `fov` (keys convert per key, eases kept). Cameras may have a parent (a null rig to orbit or crane). Known gap: a one-node camera's orientation ignores its parent's rotation (position and point of interest follow; key the camera's own rotation or use two-node). Points closer than 1 px to the camera are clipped. Camera-space coordinates are clamped to ±10⁹ px, the circle of confusion to 128 px. `effects` on a camera may hold only `control.*`; `masks`, `styles`, `matte`, `blend` are `layer.field_not_allowed`.

### 3.1 The active camera

At time *t*: the **last** camera layer in paint order (topmost) that is enabled, `visible`, and whose span contains *t*; consecutive cameras make cuts. No camera: the default two-node camera at `[w/2, h/2, −zoom₅₀]` aiming at `[w/2, h/2, 0]` with `zoom₅₀ = w · 50/36`, no depth of field, so 3D layers at z = 0 look exactly like 2D ones and gain perspective as they move in z. Projection: `(x · zoom / z, y · zoom / z) + centre`.

### 3.2 Depth of field

| Field | Type | Default | Anim. | Notes |
|---|---|---|---|---|
| `enabled` | boolean | `false` | no | |
| `focusDistance` | px | `zoom` | yes | sharp depth along the view axis |
| `focusOn` | layer id | none | no | authored: an expression measuring the camera-to-anchor depth of that layer (After Effects 26.3 "link focus to layer") |
| `focusOffset` | px | `0` | yes | with `focusOn` |
| `aperture` | px | `25.3` | yes | larger = shallower; `fStop` (authored) converts: `aperture = focalLengthPx / fStop` |
| `blurLevel` | percent | `100` | yes | scales the blur |
| `iris` | `fast` \| `triangle` \| `square` \| `pentagon` \| `hexagon` \| `heptagon` \| `octagon` \| `nonagon` \| `decagon` \| `circle` | `fast` | no | `fast` (a uniform disc with a 1-px rim) is the only kernel built; the others render as `fast` |
| `irisRotation`, `irisRoundness`, `irisAspect` | degrees, percent, number | 0, 0, 1 | yes | accepted; no effect until the polygon irises are built |
| `highlightGain`, `highlightThreshold`, `highlightSaturation` | number, linear value, percent | 0, 1, 0 | yes | accepted; no effect yet |
| `perCard` | boolean | `false` | no | blur each card uniformly by the CoC at its anchor depth (what `quality: "draft"` uses) instead of per pixel |

Blur radius per pixel: `CoC = aperture · |z − focusDistance| / z · blurLevel / 100` with `z` the camera-space depth (a tilted card blurs more at its far edge).

## 4. Camera sugar (authored only)

```jsonc
{ "id": "cam", "type": "camera", "orbit": { "center": [960, 540, 0], "radius": 2400,
    "azimuth": { "keys": [ { "t": 0, "v": -20, "ease": "sine.inOut" }, { "t": 8, "v": 20 } ] }, "elevation": 12, "roll": 0 } }
{ "id": "cam", "type": "camera", "dolly": { "target": "hero", "from": 3200, "to": 1800, "dur": 6, "ease": "power2.inOut", "at": 0 } }
{ "id": "cam", "type": "camera", "dollyZoom": { "subject": "hero", "fromZoom": 1800, "toZoom": 4200, "dur": 3 } }
{ "id": "cam", "type": "camera", "handheld": { "amount": 1, "freq": 0.7, "seed": 0 } }
```

| Sugar | Fields | Compiles to |
|---|---|---|
| `orbit` | `center` (vector3 or layer id), `radius`, `azimuth` (degrees, animatable), `elevation` (degrees, animatable), `roll` (animatable) | `pointOfInterest = center`; `position = center + radius · (sin az · cos el, −sin el, −cos az · cos el)` as an expression reading three `control.slider` effects on a generated unparented null `<camera id>.rig` (`_camrig`), keyable and exportable |
| `dolly` | `target` (layer id or vector3), `from`, `to` (distances), `dur`, `ease`, `at` | keys on `position` along the line from `target` towards the camera, `pointOfInterest` locked to `target` |
| `dollyZoom` | `subject` (layer id), `fromZoom`, `toZoom`, `dur`, `ease`, `at` | keys on `zoom` plus a position-z expression keeping `distance / zoom` constant at the subject (the Vertigo effect) |
| `handheld` | `amount` (1), `freq` (0.7), `seed` (0) | `wiggle` drivers on position (amp `8·amount` px) and rotationZ (`0.6·amount`°), two octaves |

The camera presets of [04](04-presets-and-drivers.md) §3 (`pushIn`, `pullOut`, `pan`, `orbit`, `dollyZoom`, `handheld`, `whipTo`) are built on this.

## 5. Lights

```jsonc
{ "id": "key", "type": "light", "kind": "spot",
  "transform": { "position": [500, 200, -900], "pointOfInterest": [960, 540, 0] },
  "color": "#FFF2E0", "intensity": 120, "coneAngle": 60, "coneFeather": 60,
  "falloff": "inverseSquare", "radius": 400, "falloffDistance": 500,
  "castsShadows": true, "shadowDarkness": 70, "shadowDiffusion": 24 }
```

| Field | Type | Default | Anim. | Kinds | Notes |
|---|---|---|---|---|---|
| `kind` | `parallel` \| `spot` \| `point` \| `ambient` \| `environment` | `point` | no | | `environment` is **not built** (P3): one `render.unsupported` info, ignored, not a light for the "any valid light" rule |
| `transform.position` | vector3 | `[w/2 − 200, h/2 − 200, −300]` | yes | parallel, spot, point | |
| `transform.pointOfInterest` | vector3 | `[w/2, h/2, 0]` | yes | parallel, spot | direction for parallel; aim for spots |
| `color` | colour | `#FFFFFF` | yes | all | linear working-space RGB; may exceed 1 |
| `intensity` | percent | `100` | yes | all | negative subtracts (the per-channel sum of all lights is floored at 0 after the last light) |
| `falloff` | `none` \| `smooth` \| `inverseSquare` | `none` | no | spot, point | `smooth`: linear from `radius` over `falloffDistance`; `inverseSquare`: physical, clamped to `intensity` inside `radius` |
| `radius` | px | `500` | yes | spot, point | |
| `falloffDistance` | px | `500` | yes | spot, point | `smooth` only |
| `coneAngle` | degrees | `90` | yes | spot | |
| `coneFeather` | percent | `50` | yes | spot | |
| `castsShadows` | boolean | `false` | no | parallel, spot, point | only layers with `material.castsShadows` on cast, onto layers with `acceptsShadows` |
| `shadowDarkness` | percent | `100` | yes | | |
| `shadowDiffusion` | px | `0` | yes | | percentage-closer filter radius around the receiver |
| `environment` | `{ source, intensity, rotation, background, backgroundBlur }` | | | environment | not built |

Lights affect only 3D layers with `acceptsLights` in the same comp (and, through collapsed comp layers, nested ones). A light's `in`/`out` limit when it shines; `visible: false` switches it off. A comp with 3D layers and no light renders unlit at full brightness; as soon as any valid light exists, lighting is computed and you usually want an `ambient` light too (`lint.lights_without_ambient`). A light with non-finite or out-of-range values is skipped (`layer.light_invalid`, warning). Per run: 64 lights shaded (`limit.3d_lights`, warning), 8 shadow-casting (`limit.3d_shadow_lights`, warning). Lighting is computed in scene-linear light on the camera-facing side of each card.

## 6. The classic renderer

Every 3D layer is a flat card: its pixels (through the full 2D pipeline: source, masks, effects, styles) texture-mapped onto a rectangle in 3D; text and shape cards rasterize at their on-screen scale. A card facing the camera at z = 0 with an integer screen position is pixel-exact with the 2D result; otherwise it samples through the layer's `sampling` filter. Visibility is resolved per pixel across the cards of a run (intersecting cards cut through each other; semi-transparent cards sorted back to front per pixel; `quality: "draft"` sorts per card). Lighting per pixel (ambient + Σ lights × shadow × falloff × cone). Shadows: a shadow map per casting light (parallel: one orthographic face; spot ≤ 170°: one perspective face; point or wider spot: six cube faces; 1024 texels, 512 at draft, 2048 for ≥ 4K output); a card never shadows itself; `lightTransmission` colours a semi-transparent card's shadow. Depth of field per pixel (or per card). Motion blur re-projects cards at each shutter sample. A 3D card keeps its declared bounds (a floor larger than the frame draws to its far edge). A run holds ≤ 256 drawable layers (`limit.3d_run_layers`).

## 7. Ordering of 3D and 2D layers

1. A **3D run** is a maximal sequence of consecutive drawable 3D layers in paint order (cameras and lights do not break it; any drawable 2D layer does).
2. Within a run depth decides, not array order; ties (within 1e-6 px) go to the later layer.
3. The run composites onto the backdrop as one `normal` layer at its position: 2D layers below are behind all of it, above are in front of all of it.
4. A 3D layer with a non-`normal` blend, a track matte, `preserveTransparency`, or an adjustment role is rendered on its own through the same camera and lights, composited with its mode in depth order among the other separately rendered layers **after** the shared part of the run (today it is composited over the shared part without a depth test against it; it still takes its own motion blur and casts and receives shadows across the split). A per-character 3D text layer rendered this way sorts its cards among themselves.
5. A 3D layer used as a track matte is rendered through the camera into comp space and used as a 2D matte.

## 8. 3D in nested comps

Without `collapse`, a nested comp is a flat image; if its comp layer is 3D, that image is a card, and the nested comp's own 3D layers render through the nested comp's own camera. With `collapse`, the nested 3D layers join the parent's run at the comp layer's position, transformed by its 3D transform, under the **parent's** camera and lights (the nested cameras and lights are ignored); a collapsed comp that must render as a group (effects, masks, matte, blend) forms an isolated run with the parent's camera. Mismatched `renderer3d` is `3d.renderer_mismatch`.

## 9. Interchange-only fields (not rendered)

`geometry` on text and shape layers (`extrusionDepth` 0, `bevel` `none` \| `angular` \| `concave` \| `convex`, `bevelDepth` 2, `holeBevelDepth` 100, `bevelSegments` 4; per-part materials `sides`, `bevelMaterial`, `back`); `model` layers (`asset` glTF or `primitive` `{ kind: cube \| sphere \| plane \| torus \| cylinder \| cone, … }`, `modelScale` 100, `clip`, `clipTime`, `clipSpeed` 1, `clipLoop` true, `material`, `materials`); the advanced material fields of §2; `environment` lights. They round-trip through After Effects import/export; a document that relies on them to render is `3d.advanced_not_built`.

## 10. Examples

`examples/10-3d.json`: a two-node camera with `focalLength` and depth of field (`focusOn`, `fStop`), a one-node camera cut, an `orbit` rig camera, cards at different depths with every material field, a text layer with `threeDPerChar`, a billboard (`autoOrient: "camera"`), a 3D null parent, spot/point/parallel/ambient lights with shadows, a 2D layer breaking the run, a collapsed 3D comp. `examples/10-camera-sugar.json`: `dolly`, `dollyZoom` and `handheld` on three cameras with consecutive spans. Both check with 0 errors; `10-3d.json` reports `lint.expensive_effect` on the comp (per-character 3D text with shadows and depth of field is a heavy frame), which is the point of the example.
